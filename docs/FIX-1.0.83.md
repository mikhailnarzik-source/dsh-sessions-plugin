# 1.0.83: раскладка панелей — настройка устройства, не «ожидающий файл»

После применения профиля «2 файла ждут применения» (dsh-cards/dsh-polish)
возвращались снова: host сравнивал настройки панелей, хотя `panelVisibility`
хранится в localStorage и у каждого устройства своя. Клиент применял очередь, но
локальный снимок панелей не совпадал с зеркалом — план не сходился.

## Что сделано

- `planProfilePull` больше не включает настройки вида `kind: 'browser'`
  (`panelVisibility` dsh-polish/dsh-cards) в план профиля — нечего «применять»
  на host-стороне, и план не зацикливается.
- `pullProfile` применяет браузерные настройки из зеркала **вне очереди плана**:
  если локальный снимок отличается, значение уходит в
  `browser-settings.pending.json`, клиент применит его после загрузки страницы.
  Настройки панелей продолжают ездить между устройствами, но не блокируют
  «Применить» и не висят вечно.

## Проверки

```
node --check lib/profile.mjs
node --import ./test/setup.mjs --test test/*.test.mjs   → 455/455
```

Новый `test/profile-browser-settings.test.mjs` (1): настройки панелей не попадают
в план. Существующий тест profile.test.mjs (16) подтверждает, что очередь для
клиента по-прежнему приходит.

## После перезапуска

План профиля перестанет показывать 2 файла; текущая раскладка панелей на этом
устройстве остаётся как есть (её можно менять вручную — она локальная).

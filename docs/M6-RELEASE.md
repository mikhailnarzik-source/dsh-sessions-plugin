# 1.0.76–1.0.77: правила сессий (M6, этапы 1–3)

Версия `1.0.76` — host-слой правил сессий из `22-задача-правила-сессий.md`:
хранилище, пресеты, наследование, проверки в prune/push/pull. Версия `1.0.77` —
клиентский слой, маршруты правки и «Проверить правила» (M6-B, ниже).

## Что такое правило

Набор ограничений на сессию или группу «родитель + субагенты»:

| Пресет | Для чего | Что включает |
|---|---|---|
| `control` — Контрольная | DSH JOB, DSH HOME | владелец-устройство, защита от удаления, запрет дописывания чужими, лимит размера |
| `keep` — Неприкосновенная | важная история | защита от удаления и массовых чисток |
| `archive` — Архив | старые сессии | только чтение: локальная, без отправки |
| обычная | всё остальное | без ограничений |

Флаги: `ownerDevice`, `protect`, `maxMb`, `forbidFork`, `notifyForeignAppend`,
`syncMode`, `retentionDays`.

## Хранилище и синхронизация правил

- `~/.dsh/dsh-sync/session-rules.json` — атомарная запись (tmp + rename),
  нормализация id, `updatedAt`.
- Пресеты раскладываются в поля при создании правила; правило родителя
  наследуется субагентам (`lib/session-groups.mjs`), ребёнку своё правило можно
  задать с предупреждением.
- `rules-history.jsonl` — журнал изменений; `profile/session-rules.json` —
  копия в профиле, чтобы правила приезжали на второе устройство.
- Merge по `updatedAt` (свежее побеждает, при равенстве — локальное + конфликт
  в истории).

## Проверки

- **prune / удаление:** сессии с `protect` не удаляются, в плане строка
  «защищена правилом» (`protectedByRule`).
- **push:** `ownerDevice` ≠ это устройство → пропуск, `reason: 'rule-owner'`;
  `syncMode: 'local'` → пропуск; при `maxMb` в отчёте `overLimit/mb/message/
  suggestion` (автопереход в локальные — только при `autoLocal`).
- **pull:** входящее изменение лога не от владельца → предупреждение и конфликт
  без перезаписи; `notifyForeignAppend` — уведомление; `forbidFork` — копия не
  создаётся.
- `summary.ruleFields[]` и `summary.rules{count,protected,ownerBlocked,
  overLimit,localSkipped,…}` — данные для карточки в панели.

## M6-B: интерфейс и маршруты правил (1.0.77)

Версия `1.0.77` — клиентский слой и маршруты правил сессий поверх host-слоя
`1.0.76`.

**Маршруты.** `GET /api/dsh-sync/session-rules` — сводка (`rules`, `counts`,
`sessions` с полями правила, `history`, `lastRun`, `profile`, без секретов);
`POST` на тот же путь — `{id|ids, preset?, patch?}` и `{clear:true}`, ответ
`{ok, action, updated, ids, warnings}`; `GET /api/dsh-sync/session-rules/verify`
— «Проверить правила» только для чтения (`buckets`, `sources`, `conflicts`,
`lines`, `changes:false`). Правка пишется в `rules-history.jsonl`
(`kind: session-rule-set|session-rule-clear`) и в `profile/session-rules.json`;
при чтении копия из профиля сливается (`mergeRulesFromProfile`).

**Интерфейс.** Меню сессии → «Правила сессии…»: чипы пресетов
(Контрольная/Неприкосновенная/Архив/Обычная), поля (владелец-этот компьютер,
защита, лимит МБ, запрет форка, уведомлять), «Сохранить» и «Проверить правила».
В карточке «Сессии и режим» — блок «Правила»: фильтр
все/защищённые/контрольные/архив, щиты, бейджи пресета/владельца/лимита,
«Проверить правила» с отчётом корзинами. В списке сессий — щит и бейдж
«лимит: X/Y МБ», «правило: только владелец», «изменено не владельцем», баннер
«Сессия выросла до X МБ — перевести в локальные?» (при `autoLocal` — без
вопроса). Правила по гайду: карточки 14, кнопки 36/32, чипы 32, адаптив 640,
внутренний скролл списка правил, hover/focus.

**Проверки.** `test/m6-ui.test.mjs` — 17 тестов: маршруты get/post/verify,
раскладка пресетов, наследование с предупреждением, снятие правила, бейджи
ownerBlocked/overLimit, только-чтение проверки, merge с профилем и конфликт,
рендер карточки/фильтра/щитов/модалки/баннера, адаптив и скролл.

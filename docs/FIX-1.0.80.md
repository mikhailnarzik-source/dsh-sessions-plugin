# 1.0.80: фантомные объявления «локальная» больше не размножаются

Шаг 1 уборки после инцидента 25.11: режимы сессий снова «уплывали» — в зеркале
оставались объявления «локальная навсегда» для несуществующих сессий, и каждая
синхронизация возвращала их в `session-modes.json`.

## Причины

1. `publishLocalOnly` объединял домашний реестр и зеркало (union). Зеркало
   содержало старые записи, поэтому удалённые дома объявления воскресали.
2. Push сначала делал `fetch + reset` дерева зеркала: исправленный
   `local-only.json` затирался удалённой версией ещё до коммита.
3. `applyLocalOnlyModes` создавал режим `local` даже для id, которых нет в сторе.
4. Устаревший запрос из UI мог вызвать `makeSessionLocal` для несуществующей
   сессии — появлялись объявление, метка `made-local` и режим-фантом.

## Что сделано

- **Фантомные режимы:** `applyLocalOnlyModes` принимает `existingIds`
  (`onlyExisting: true`); `enforceLocalOnly` передаёт реальные id из
  `~/.dsh/sessions`. Для несуществующих сессий режим не создаётся.
- **Снимок дома сильнее зеркала:** если `updatedAt` домашнего реестра новее
  зеркала, записи зеркала, которых нет дома и которые старше снимка, снимаются.
  Более поздние чужие объявления сохраняются.
- **Push перепубликует объявления:** после `fetch + reset` вызывается
  `publishLocalOnly`, поэтому в зеркало уходит актуальный домашний набор, а не
  устаревший с удалённого устройства.
- **Защита от устаревших запросов:** `makeSessionLocal` возвращает
  `session/not-found`, если сессии нет ни в сторе, ни в зеркале — без режима,
  объявления и метки.

## Проверки

```
node --check lib/session-modes.mjs lib/cloud-copy.mjs lib/sync.mjs
node --import ./test/setup.mjs --test test/*.test.mjs   → 421/421
```

Новый `test/modes-phantom.test.mjs` (4 теста): фантомные id не создают режимы;
`makeSessionLocal` отказывает несуществующей сессии; домашний снимок снимает
фантом из старого зеркала; совместимость без `onlyExisting`.

## Что осталось сделать после перезапуска

1. Перезапустить DSH (загрузится 1.0.80).
2. Один `push`: зеркало получит исправленный `local-only.json` (одна запись).
3. Проверить: `локальных 1, облачных 24`, в зеркале одна заявка.

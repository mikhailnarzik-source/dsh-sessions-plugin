# 1.0.78: развилки сессий создаются один раз

Симптом: после нескольких синхронизаций в списке появлялись десятки одинаковых
«DSH HOME» — каждая синхронизация при расхождении логов создавала новую
сессию-копию с новым id.

## Причина

В pull при конфликте «обе стороны дописали разное» удалённый лог сохранялся
отдельной сессией (`session-${randomUUID()}`). Если удалённая копия не менялась,
следующие синхронизации создавали её снова и снова — по одной за запуск.

## Что сделано

- Перед созданием развилки проверяется, не импортирована ли уже точная копия
  удалённого лога (по `contentHash` через `findDuplicateAmongLogs`). Если да —
  конфликт фиксируется в отчёте (`forkExists`, `forkSkipped`), новая сессия не
  создаётся.
- Правило `forbidFork` по-прежнему полностью запрещает развилки.
- Реальные расхождения один раз сохраняются отдельной сессией (потерять
  события нельзя), но больше не размножаются.

## Уборка на этой машине

- 10 копий большой сессии (по 38,5 МБ, 384,8 МБ) убраны в карантин, затем
  карантинные копии удалены, в зеркале оставлены метки `superseded` —
  повторно не приедут.
- Расходящаяся зеркальная копия живой DSH HOME снята с меткой `superseded`:
  дома остаётся живой лог, лишняя копия не возвращается.
- Зеркало: рабочее дерево 1226 → 455,7 МБ, `.git` 509 МБ после `git gc`.

# M1: идентичность, дубли, локальные сессии — 1.0.68

Версия `1.0.68` закрывает M1 из аудита 24.11 (папка `DSH-домой-2026-11-24`):
идентичность сессий, дедупликация, каноническое восстановление, «локальная навсегда»,
агрегация расходов вынесена в `dsh-expenses 0.4.14`.

## Что вошло

### Идентичность и дубли (dsh-sessions)

| ID | Что | Файлы |
|---|---|---|
| D1 | `contentHash` (sha256 нормализованного лога: id→ID, cwd→CWD) и `lineageKey` (createdAt+title+cwd) в `session.json`; ленивая миграция старых sidecar без перезаписи логов | `lib/catalog.mjs` |
| D2 | Импорт/pull сравнивает содержимое: копия с тем же хешем не создаёт новую сессию (`reason: duplicate`, `duplicatesSkipped`); седьмая корзина «Дубли» в плане | `lib/plan.mjs`, `lib/sync.mjs` |
| D3 | «Найти дубли»: маршрут `POST /api/dsh-sync/duplicates` (read-only) и `POST /api/dsh-sync/duplicates/quarantine` (с `confirm:true`), CLI `dsh-sync duplicates`; лишние копии — в карантин с `reason: duplicate`, каноническая не трогается; клиент — корзина «Дубли», карточка групп, подтверждение | `index.js`, `client.js`, `cli.mjs` |
| D4 | Детерминированный рейтинг (lastEventAt → events → bytes → children → createdAt → id) и канонический id (id с детьми) при восстановлении: `restoredFrom`, проигравшие `superseded` | `lib/deletions.mjs`, `index.js` |

### Локальная сессия «навсегда» (24/08)

- `local-only.json` в зеркале: объявление «эта сессия локальная» переживает `fetch+reset`,
  перезапуск и push с другого устройства.
- «Убрать копию из облака»: режим `local` + объявление + облачный каталог в карантин
  `_deleted` с `reason: made-local`; офлайн — операция в outbox.
- «Сделать облачной»: снять объявление/метку и отправить сессию.
- Переключатель «Облачная / Локальная» в шапке открытой сессии, мини-меню с пояснениями,
  одно подтверждение, тост «Отменить» (10 с). Кнопка миграции «Убрать облачные копии
  локальных сессий (N)».

### Расходы (dsh-expenses 0.4.14)

- Одна строка на логическую сессию: линия по `parentSession` → `contentHash` →
  `createdAt`+название; копии не складываются («+N копий»), субагенты входят в родителя
  (рекурсивно, «субагентов: N» с разбивкой), карантинные записи учитываются.
- Названия из `session/title` (кэш по mtime; fallback «Без названия», первое сообщение —
  в подсказке), `titleSource`.
- Локальные сессии из `session-modes.json` (только чтение): бейдж «локальная», фильтр
  все/облачные/локальные, локальные всегда в итогах; диагностика «в архиве N, показано N,
  локальных M».
- Живой прогон: 99 записей → 41 логическая сессия, 43 субагента и 15 копий свёрнуты,
  90 названий из `session/title`.

### Тестовая инфраструктура

- `test/setup.mjs`: у каждого тестового процесса свой временный `DSH_HOME` — тесты
  больше не пишут в реальный профиль; полный набор проходит параллельно.
- `test/plugin-smoke.mjs`: список маршрутов обновлён (`duplicates`, `duplicates/quarantine`,
  `local-only-migration`).

Живые read-only прогоны: план по реальному зеркалу — `duplicates: 0` (ложных нет),
`same: 11`, `localAhead: 2`; `dsh-sync duplicates` — канонический id живой, лишних живых
копий нет; `writeCatalog` на копиях реальных сессий — логи байт-в-байт целы.

## Что сделать рабочему компьютеру

1. Обновить `dsh-sessions` до 1.0.68 и `dsh-expenses` до 0.4.14, перезапустить DSH.
2. Удалить ручные патчи `*.bak-before-*` из `node_modules` — H1/H2 теперь в исходнике.
3. Прогнать регрессионный чек-лист (`18-ПЛАН-РАБОТ.md` §4).
4. Проверить: «Найти дубли» не находит ложных; «убрать копию из облака» держится после
   3 циклов; восстановление даёт одну сессию с тем же id; расходы — по одной строке
   на сессию, субагенты в родителе, локальные с бейджем.
